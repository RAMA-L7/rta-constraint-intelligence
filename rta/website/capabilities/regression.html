Constraint drift becomes a reviewable event

Versioned snapshots and semantic baseline diff — NEW, RESOLVED, CHANGED, UNCHANGED — so constraint evolution is auditable from one release to the next.

The problem

Text diff can't see semantics

Two SDCs can be textually different but semantically identical, or textually similar but semantically different (a changed period, a dropped clock, a wildcard drift). Semantic diff sees the intent.

What makes it semantic

  • Structured identity — findings matched by constraint semantics, never by line number or message text
  • Readiness delta — how the readiness verdict moved and why
  • Coverage & trust deltas — newly constrained, newly unconstrained, context changes
  • Baseline compatibility — schema-aware; incompatible baselines are reported, not guessed
◈ What regression diff does not mean. A clean diff means no disallowed readiness regression was detected — it does not certify the new constraints are timing-correct.
