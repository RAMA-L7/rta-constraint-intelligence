Capability · Constraint Coverage

Which objects does the SDC actually describe?

Coverage is reported at object level — inputs, outputs, buses — with exact constrained ranges. And the product always says what coverage is not: correctness.

The problem

A percentage hides the gaps

"95% coverage" tells you nothing about which bus is half-constrained or which pin has no delay. Object- and bit-level evidence does.

Statuses

CONSTRAINED object fully described by the SDC
PARTIAL only part of the object / bus is covered
UNCONSTRAINED no constraint references it
EXEMPT excluded by a documented exception
UNKNOWN / N/A unresolvable or not applicable

▲ Coverage ≠ correctness. A fully constrained object does not prove correct timing intent. An exempt object is not verified correct. Coverage answers "is this described?" — not "is this right?"
◈ What coverage does not mean. It is not a timing analysis of the constrained paths, and it is not a pass/fail on the design. It is an evidence inventory for the engineer to review.
