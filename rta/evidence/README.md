# Ṛta — QA Benchmark Suite

Reusable, rerunnable end-to-end benchmark for the Ṛta (checker, linter,
converter, clock-relations, coverage, wildcard analyzer, constraint diff) and the
Streamlit web UI (local or deployed).

## Phase 2 — Golden verification suite (2026-08-04)

> **Historical diagnostic (Phase 2, 2026-08-04).** Current evidence is in
> `benchmarks/RTA_FOUNDATION_REPORT.md` and the canonical source of truth is
> `RELEASE_EVIDENCE.json` (verified by `benchmarks/build_evidence.py --check`).

Diagnostic phase: every prior finding was re-run as a minimal reproducer, compared against
authoritative Tcl(n)/SDC command semantics, and classified. No production code was changed.

```
benchmarks/
  golden/                         # 22 deterministic high-confidence cases
    manifest.json                 #   machine-readable expectations (correct behavior, not tool output)
    run_golden.py                 #   runner → golden/results.json
    01_comments … 12_regressions/ #   focused minimal SDC inputs
  verify_findings.py              # F01–F14 minimal reproducers
  test_ui_state_isolation.py      # repeated analyze / input-switch / view-switch (6/6 pass)
  GOLDEN_BENCHMARK_VERIFICATION_REPORT.md   # full verification report
```

Run all phase-2 checks:

```bash
python benchmarks/run_golden.py               # 10/22 pass today — 12 failures = confirmed bug backlog
python benchmarks/test_ui_state_isolation.py
```

**Golden results today:** 10/22 cases match correct behavior. The 12 failing cases are the
verified bug backlog (comments, multiline continuation, scientific notation, Tcl variables,
SDC-007 word boundary, braced clock groups, uncertainty flag-order) and act as permanent
regression targets — they are expected to flip to pass as production code is fixed.

## Layout

```
benchmarks/
  run_benchmark.py        # module-level runner → results/results.json
  test_ui_app.py          # Streamlit AppTest UI benchmark (33 checks)
  valid/                  # golden SDC files (clean or near-clean)
  invalid/                # SDC files with intentional errors
  edge_cases/             # boundary / encoding / multiline / comment attacks
  clock_relations/        # sync, async, physically-exclusive, generated chains
  timing_exceptions/      # false path, multicycle, max/min delay, disable timing
  io_constraints/         # input/output delay variants, driving cell, load
  malformed/              # garbage, truncated, conflicting, duplicated input
  large_design/           # 24-clock design; 3000-line design (perf)
  regression/             # copies of samples/ used by the Test Drive tab
  results/results.json    # machine-readable output (regenerated by the runner)
```

## How to run

```bash
python -m pytest tests/ -q                 # project's own unit suite (baseline)
python benchmarks/run_benchmark.py         # module-level benchmark → results.json
python benchmarks/run_benchmark.py -q      # summary only
python benchmarks/test_ui_app.py -v        # Streamlit AppTest UI benchmark
python cli.py check <file.sdc>             # spot-check a single file
```

Local web UI (for manual checks): `streamlit run app.py --server.port 8501`

> The deployed instance (https://sdc-tools-8mxtuhwy5myvejdcmpuwbp.streamlit.app/)
> ran v1.3.0 — the same code as this repository at benchmark time. **Note:** it has
> since become **auth-gated** (303 → share.streamlit.io/-/auth/app) and can no longer
> be exercised anonymously; re-enable public access to rerun the UI benchmark there.

## Known tool limitations discovered (detailed in QA_REPORT.md)

1. Comments are NOT stripped → phantom commands/constraints (false errors/warnings).
2. Backslash-continuation content is dropped by line-limited regexes.
3. Tcl variables are not resolved by the checker.
4. Scientific notation values are mis-parsed.
5. SDC-007 `\b...\b` fails on names like `data_in`.
6. SDC-022/023 never fire for standard `-setup/-hold`-first syntax.
7. Braced clock-group lists (`[get_clocks {a b c}]`) are not handled.
8. SDC-020 is noisy on legitimate reset/CDC false paths.
9. Unsupported commands are silently ignored.
10. No conflicting-constraint detection.
11. Issue line numbers are mostly 0.
12. Test Drive sample descriptions drift from actual behavior.
